# Standards — Checklist

Generic baseline. Every item here is mandatory unless the repo's own conventions override it —
`/agent-review:init` appends the repo-specific checklist, and both layers are kept.

This is an explicit checklist: report compliance for each **bold group below** in the
`### Rule Checklist Results` section of your output (✅ / ⚠️ / ❌ / N/A), and raise anything
non-compliant as a finding at the severity its impact warrants.

**Exports & Naming**

- [ ] Export style matches the repo's convention (named vs default) — don't introduce a second style
- [ ] File and directory naming follows the existing convention (casing, suffixes, special filenames
      the framework requires)
- [ ] Public identifiers are descriptive; abbreviations match ones already used in the codebase
- [ ] Imports use the repo's alias/path convention rather than deep relative traversal

**Types**

- [ ] No escape hatches that disable type checking in new code (untyped `any`-equivalents, suppression
      comments) without an inline comment explaining why
- [ ] No non-null/force-unwrap assertions on values that can legitimately be absent — check explicitly
- [ ] Types are derived from a single source of truth rather than hand-duplicated alongside it

**Input & Forms**

- [ ] User input is validated with the repo's established validation approach, not ad-hoc checks
- [ ] Every client-side validation rule has a server-side counterpart
- [ ] Submit/confirm actions are disabled or guarded while in flight so they can't double-fire

**Data**

- [ ] Writes invalidate or update the cached data they affect
- [ ] Cache/query keys are stable, descriptive, and scoped to the resource and its inputs
- [ ] Queries rely on the real authorization boundary, not on a client-side filter

**Dates & Numbers**

- [ ] Date math uses the repo's chosen date library and format conventions, not ad-hoc arithmetic
- [ ] Numeric formatting and rounding happen at the display boundary, consistently

**Testing**

- [ ] Every new function, hook, and non-trivial component has a test in the repo's conventional
      location
- [ ] Tests use the repo's runner and mocking idioms
- [ ] Test code is typed as strictly as production code

**Code Quality**

- [ ] Lint, type-check, and format commands pass
- [ ] No debug output left behind (console/print statements, debuggers, `TODO` without a tracked issue
      reference)
- [ ] No unused imports, variables, or dead parameters
- [ ] No commented-out code blocks (delete, don't comment)
- [ ] No empty catch blocks that swallow errors silently
- [ ] Package-manager usage matches the repo's lockfile (don't mix tools)

## Repo-specific: familylife-gift-cards

This is a Ruby 3.3 / Rails 8.1 app. Ruby has no type checker here, so the generic "Types" group maps to Ruby habits (see Models below). The groups below add to the generic ones. Report them under the matching bold group.

**Exports & Naming**

- [ ] Files follow Rails autoload naming. One class per file, `snake_case.rb`, constant name matches the path (`app/models/custom_authorization.rb` is `CustomAuthorization`, `app/controllers/api/v1/gift_cards_controller.rb` is `Api::V1::GiftCardsController`). API controllers use the compact form `class Api::V1::GiftCardsController < Api::V1::ApplicationController`, not nested `module` blocks.
- [ ] Admin files are `app/admin/<plural_resource>.rb` with `ActiveAdmin.register <Model>`. Admin view helpers go in `app/admin/active_admin/views_helper.rb` (`module ActiveAdmin::ViewHelpers`).
- [ ] Model constants are SCREAMING_SNAKE in the owning class and strings, not symbols: `GiftCard::TYPE_PAID_HALF_PRICE = "paid_half_price"`, `TYPE_PAID_FULL_PRICE`, `TYPE_PAID_OTHER`, `TYPE_DEPT = "type_dept"`, plus `PAID_TYPES` and `TYPE_DESCRIPTIONS` (value to label). New gift card types must update `TYPE_DESCRIPTIONS`, `PAID_TYPES` if paid, `Batch` validations and the batch admin form. Look for: raw `"paid_full_price"` / `"type_dept"` string literals outside `GiftCard`. Use the constants (as `Batch`, `Issuance` and `app/admin/batches.rb` do). Other constants follow the same style (`Issuance::CERTIFICATE_DISPLAY_SEPARATOR`, `FamilylifeGiftCards::HEALTHCHECK_ACTION`). Do not repeat `", "` as a literal.
- [ ] Gift card vocabulary stays consistent: `certificate` (the voucher number), `registrations_available`, `associated_product`, `gl_code`, `dept`, `isbn`, `gift_card_type`, `allocated_certificates`. Do not introduce synonyms (`code`, `number`, `uses_left`, `sku`) for these.
- [ ] Namespaces: `Api::V1` for the API, `Admin::` is generated by ActiveAdmin (`Admin::IssuancesController`). Do not create a hand-written `Admin::` controller.
- [ ] Routes: the API is declared as `namespace :api do namespace :v1 do resources :gift_cards, only: [:show, :update]` in `config/routes.rb`. Keep `only:` lists tight.

**Models and Ruby habits (stands in for "Types")**

- [ ] Every model defines both `self.ransackable_attributes(auth_object = nil)` and `self.ransackable_associations(auth_object = nil)`. Attribute names must be real columns or attribute methods, association names real associations. Spec files assert this. Look for: a new model or column with no ransack allowlist update, or an allowlist entry added "just to make a filter work" for a sensitive column.
- [ ] Validations use the style in the file. `Batch` uses `validates_presence_of ... if: -> { ... }` with lambda conditions and `validates :gift_card_type, inclusion: {in: GiftCard::TYPE_DESCRIPTIONS.keys}`. `GiftCard` and `Issuance` use `validates :attr, ...`. Do not mix a third style into a file.
- [ ] Associations are plain `belongs_to` / `has_many` with `class_name:` for user roles (`creator`, `issuer`). Optional associations say `optional: true`.
- [ ] State changes on `Issuance` go through AASM events (`preview!`, `issue!`). Do not assign `status` directly in app code (`update_column(:status, ...)` is test setup only).
- [ ] Delegation and display: `delegate :price, to: :batch, allow_nil: true` style, and `to_s` for admin display names (`Batch#to_s` returns `description`).
- [ ] No force-unwraps of values that can be nil. `price`, `expiration_date`, `registrations_available` and `gl_code` can all be nil on some records. Use `.to_i`, `&.`, or `.present?` as the surrounding code does.
- [ ] Callbacks (`after_initialize`, `before_save`, `after_create`, `before_create`) stay short and named after one job. Long logic goes in a named public method (`set_allocated_certificates`), as in `Issuance`.
- [ ] `ApiKey`, `User` and other models keep one concern. Auth hash handling stays in `User.find_or_create_from_auth_hash` / `#apply_auth_hash`, not in `SessionsController`.

**ActiveAdmin habits**

- [ ] Every `ActiveAdmin.register` has an explicit `permit_params` listing only fields an admin may set. Do not remove it, and do not add a field without a form input or a clear reason.
- [ ] Scope actions with `actions :all, except: [...]` where the app wants to block them (`Batch` has no destroy, `GiftCard` has no new). Do not hide a button in the UI and leave the action routable.
- [ ] Authorization goes through the one `CustomAuthorization` adapter (`config.authorization_adapter = "CustomAuthorization"`). `authorized?(action, subject)` returns true for `:read`, is false for any non-read action on an issued `Issuance`, and true otherwise. Do not add per-resource `if:` guards in `app/admin/*.rb` for the same rule.
- [ ] Money display uses the `activeadmin_addons` helpers already in use: `column :price, as: :currency`, `number_column :price, as: :currency, unit: "$"`, `tag_column :status`. Use `as: :date_picker` for date inputs. Do not hand-format currency with string interpolation. Sortable computed columns pass `sortable:` (see `app/admin/gift_cards.rb`).
- [ ] Index columns rename long labels with a quoted first arg (`column "Reg'n Avail", :registrations_available`, `column "Expn Date", :expiration_date`). Keep that short-label habit for new wide columns.
- [ ] Forms use `form do |f| f.semantic_errors ... inputs do ... end f.actions end`. Show/hide of fields by gift card type is done by reloading the form with a `gift_card_type` query param through `reload_js_based_on_gift_card_type`. Reuse that, do not add custom JS.
- [ ] `filter` lines name real attributes or associations, and the name is also in `ransackable_attributes` / `ransackable_associations`. A typo does not fail loudly: `filter :quantitiy` in `app/admin/issuances.rb` passes the index spec today. Do not copy it.
- [ ] Custom admin routes use `member_action :name, method: :put` plus an `action_item :name, only: :show, if: -> { resource.<state?> }` whose link uses `method: :put` and `data: {confirm: "..."}` (see `issue`). `before_create do |record| ... end` is the hook for setting `creator`.
- [ ] Do not leave the generated scaffold comment blocks and commented-out `permit_params do` examples in files you create or heavily edit. The generated ones in older files are not a model to copy.

**Controllers**

- [ ] API controllers inherit from `Api::V1::ApplicationController` (token auth, `skip_forgery_protection`). Use `before_action` for loading a record (`load_gift_card_from_certificate`) and `render json: {error: "...", status: 404}, status: :not_found` for errors. Keep the `error` key.
- [ ] Non-API controllers inherit from `ApplicationController`. Auth redirect lives in `authenticate_active_admin_user!`. Login callback is `SessionsController#oktaoauth` (`Devise::OmniauthCallbacksController`).
- [ ] Do not repeat a lookup that a `before_action` already did. (`Api::V1::GiftCardsController#show` re-runs `find_by` after `load_gift_card_from_certificate`. Do not copy this.)
- [ ] `protected` for helpers in controllers that subclasses use, `private` for the rest (`Api::V1::ApplicationController` uses `protected`, `GiftCardsController` uses `private`).

**StandardRB style (the only linter)**

- [ ] `bundle exec standardrb --format simple` is clean. There is no `.rubocop.yml` or `.standard.yml`, so defaults apply. `Gemfile` has `gem "standard"` and an explicit comment that rubocop-rails-omakase is not adopted. Do not add either.
- [ ] Double-quoted strings: `"text"`, `%w[...]` for word lists (`%w[description gift_card_type ...]`), hash shorthand without spaces inside braces (`{error: "x"}`, `{in: [...]}`, `params: {access_token: ...}`), `unless` for simple negative guards, trailing-comma-free multi-line args aligned as StandardRB formats them. `# frozen_string_literal: true` appears in some files and not others (for example `SessionsController`, `app/admin/dashboard.rb`, some initializers and specs). Do not mass-add or mass-remove it.
- [ ] Two-space indent, no trailing whitespace, no semicolons, no `and`/`or` for control flow in new code.

**Input, Forms and Data**

- [ ] User and API input is checked by model validations first (`Batch` presence/inclusion, `Issuance` `quantity` numericality), and the admin form mirrors them. A new required field needs both a model validation and a form `input`.
- [ ] Use ActiveRecord scopes/queries with bound params (`where("certificate ~* ?", pattern)`, `GiftCard.find_by(certificate: ...)`). No string interpolation of request values into SQL.
- [ ] Multi-row issuance writes stay inside the AASM transition (`after: :create_gift_cards`) or a `transaction`. Do not add loose save loops in controllers.
- [ ] Admin submit buttons use ActiveAdmin's form actions (`f.actions`, `f.action :submit, as: :button, label: "..."`). Destructive or irreversible links carry `data: {confirm: "..."}`.

**Dates and Numbers**

- [ ] Use `Date.current` and `Time.current` (the app zone), as `GiftCard#expired?` does. Do not add new `Date.today` or `Time.now` (there are a few old ones in `app/admin/issuances.rb`).
- [ ] Money is `BigDecimal` from `decimal(8,2)` columns (`price`). Never `Float`, `to_f` or `round` in a pipeline. Round only for display. Certificate prefix math (`batch.price.to_i`) is the only place `price` becomes an integer.
- [ ] New migrations use the current Rails tag (`ActiveRecord::Migration[8.1]`). The existing 7 files say `[7.2]` only because they predate the upgrades. Commit the regenerated `db/schema.rb` in the same PR.

**Testing (repo layout and idioms)**

- [ ] RSpec with `require "rails_helper"` at the top. Models: `RSpec.describe Issuance, type: :model do`. Files are `spec/<area>/<name>_spec.rb`. Use `context "#method_name"` / `describe "GET index"` headings, `let` / `let!`, and `create(:factory)` from FactoryBot (included globally).
- [ ] Factories live in `spec/factories/*.rb`. Use the existing `:batch_paid`, `:batch_dept`, `:issuance`, `:gift_card`, `:user`, `:api_key` factories instead of inline records. Add new variations as child factories or traits.
- [ ] ActiveAdmin specs live in `spec/controllers/admin/<resources>_controller_spec.rb`. They use `type: :controller`, `render_views`, `require "capybara/rails"`, `sign_in @user` (from `Devise::Test::ControllerHelpers`) and Capybara matchers (`have_content`, `have_field`) on `response.body`.
- [ ] API specs live in `spec/controllers/api/v1/`. They set `request.env["HTTP_ACCEPT"] = "application/json"`, pass `format: :json`, assert `have_http_status(...)` and `JSON.parse(response.body)`.
- [ ] Model specs assert the ransack allowlists exist (`Model.ransackable_attributes.each { |a| expect(Model.column_names).to include(a) }`). New models copy that.
- [ ] No debug output (`puts response.body` exists in `issuances_controller_spec.rb`; do not copy it), and no `binding.irb`, `binding.pry` or `debugger` left behind.
- [ ] No `focus: true`, `fit`, `fdescribe` or `fcontext`. `spec/spec_helper.rb` sets `filter_run_when_matching :focus`, so one focused example makes CI run only that example and the rest of the suite silently skips.
- [ ] Use `expect(...).to receive(...)` only for methods on the object under test or for external calls (`verify_partial_doubles` is on, so stubbed names must exist).

**Commands to run (quoted from the repo)**

- [ ] Lint, from `.github/workflows/ruby.yml` job `lint`: `bundle exec brakeman -A -q --no-pager` and `bundle exec standardrb --format simple`.
- [ ] Tests, from job `test`: `bundle exec rails db:create`, `bundle exec rails db:schema:load`, `bundle exec rspec --color` (CI also sets `RAILS_ENV: test`).
- [ ] Audit, from job `audit` (not required): `bin/bundler-audit check --update` and `bin/importmap audit`.
- [ ] Local full run, `bin/ci` (`config/ci.rb`): `bin/setup --skip-server`; `env RAILS_ENV=test bin/rails db:create db:schema:load`; `bundle exec standardrb --format simple`; `bin/bundler-audit check --update`; `bin/importmap audit`; `bin/brakeman --no-pager`; `env CI=true RAILS_ENV=test bundle exec rspec --color`.
- [ ] `lint` and `test` are required checks on `main`. Do not rename those jobs.

**Code Quality extras**

- [ ] No leftover scaffold: commented `permit_params` examples, dashboard example blocks, `import.rb` style one-off scripts added to the app.
- [ ] Gems: Bundler only (`Gemfile.lock`), no `package.json`. JS is importmap (`config/importmap.rb`, `bin/importmap`). Do not add npm tooling.
- [ ] Locale strings live in `config/locales/en.yml` only (ActiveAdmin dashboard text uses `I18n.t`). Do not add other locale files.
- [ ] Logging goes through the existing lograge + Ougai JSON setup (`config/initializers/lograge.rb`, `lib/log/logger*`). No `puts` or `p` in app code.
